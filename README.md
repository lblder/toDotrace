# TodoAgent · 每日打卡工作台

个人科研工作台：每日到实验室打卡、按微软待办模型管理日/周/项目计划、
规范化导入导出、热力图与四维综合评价。本地服务 + 多账号（邀请码注册），
数据全部保存在本机 SQLite，不依赖任何云服务。

**阶段 1（骨架与账号）已完成。** 两个账号可注册登录、数据按账号隔离、
无令牌请求一律被拒——三条验收标准均经独立验证（见下）。

## 开始日常使用

```sh
双击 启动.command        # 构建（如需）→ 起服务 → 打开浏览器
```

打开后：首启引导创建 owner → 打卡页点「到达」→ 离开时点「离开」。

**当前能力边界（截至阶段 3，如实列出）**：

- ✅ 打卡（到达 / 离开 / 休息日 / 连续天数）、多账号（邀请码注册）、局域网访问
- ⏳ **还没有计划/任务管理**（阶段 4）、**没有导入导出**（阶段 5）、**没有热力图与评价**（阶段 6）
- ⚠️ **没有任何更正手段**：打错了不能改也不能删——撤销入口属阶段 5。
  在此之前请把打卡当作「记下就是记下了」。
- ⚠️ **备份**：`data/app.db` 是全部数据。服务停止时复制该文件即完整备份；
  运行中请勿直接复制（见下方「数据与备份」）。

**已知限制**（逐条如实记录，不当作已解决）：

- 持一个有效邀请码可枚举「某用户名是否已注册」。注册表单必须能告知失败原因，
  故此行为**裁决保留**；残余风险与重评触发条件见
  [ADR-008](./docs/adr/008-阶段1-服务端接口与表结构.md) §「后果」。**不是已修复，是已接受。**
- 浏览器测试**只跑 Chromium**（webkit/firefox 的浏览器二进制未安装）。
- 权限按资源的**归属闸门尚未存在**——阶段 1 没有任何按 id 取单条资源的接口，
  越权防护要等阶段 2/3 出现 `:id` 资源后才真正被行使。届时须复用同一关口。
- **覆盖导入当前会「清空账号」而不是「替换为文件内容」**——覆盖面用事件 id 划界，
  而导入的事件保留原 id（更早），于是被自己的覆盖面排除。**旧数据与设置一起不可见、
  文件内容也进不来，且无任何报错。** 三条同族缺陷已记入
  [ADR-004](./docs/adr/004-覆盖面与覆盖导入.md)，**阶段 5 必须先解决这个地基问题**；
  在那之前，不要按任何「缓解措施」实现覆盖导入——**已有一条被实测证伪**。
- **跨账号隔离防线只能挡「漏填」、挡不住「填错」**：`RoundCompletion.accountId`
  漏填会抛错（响亮），填错则静默采纳。故阶段 4 接入时 **`accountId` 必须取自鉴权上下文，
  不得来自请求体**——阶段 2 尚无调用方，没有代码强制这一点。
- **一次到访跨过「一天边界」时，时长会被算成很大**：到达 10-01 未离开、10-02 再点离开，
  会把 10-01 那一行闭合、时长 = 24 小时。原因：`23:00→次日05:00`（通宵）与
  `10:00→次日10:00` 在**归属日坐标上完全同构**，区分它们只能靠一个凭空的小时阈值。
  **阶段 6 计算投入时长时必须显式决定**（计入 / 按 FR1「不猜测」视为未知 / 设上限），
  **不得在不知情下算成 24 小时**。
- **`isRestDay === false` 是二值的**（有记录 **或** 尚未到达）：未来日上它与
  `countCheckins` 不再互补。**阶段 6 的热力图正是"用它反推那天有没有记录"的写法**，
  实现时须显式处理三态（空白 / 未到 / 休息）。

## 快速开始

需要 **Node 22+**（`engines` 已声明；原生依赖 better-sqlite3 在 Node 22 上实测走预编译二进制，无需本地编译）。

```sh
npm install          # 安装依赖

npm run dev          # 开发：前端 dev server + 后端服务并跑（热更新）
npm run build        # 构建前端产物到 dist/
npm start            # 使用：单进程托管 dist/ 与 API

npm test             # 全部单元测试（vitest）
npm run typecheck    # 类型检查
```

**日常使用**：双击 `启动.command` —— 检查构建 → 启动服务 → 打开浏览器。
脚本会在端口被占用时自动顺延，并提供「开放局域网」选项（会明示明文 HTTP 的风险）。

### 浏览器测试（前端交互）

```sh
npx playwright install chromium   # 首次需下载浏览器（约 150MB）
npm run test:browser
```

界面行为（路由守卫、主题首帧、表单错误分流、可访问性）只有真实浏览器能验——
开发期已多次出现「SSR/tsx 验证全绿、真实浏览器里却卡死」的情况，故单列一套。

> ⚠️ **`@playwright/test` 精确锁定在 `1.60.0`，不要加 `^`。**
> 浏览器二进制与 Playwright 版本是**绑定**的：放宽版本号会让 npm 装到新版，
> 而缓存里的浏览器属于旧版，症状是「包装好了，但浏览器启动不了」。
> 本项目已踩过一次——错装 1.63 后三个引擎全部无法启动，而报错只提到路径不存在。

### 端口

默认 **8788**（不是更常见的 8787——开发机上 8787 长期被另一个进程占用，
且那个占用者会返回非本项目的响应格式，症状极易被误认为「后端没实现」）。

一律可用环境变量覆盖，**代码中无任何地址/端口硬编码**（架构文档 §1）：

```sh
TODOAGENT_API_HOST=0.0.0.0 TODOAGENT_API_PORT=9000 npm start
```

## 数据与备份

全部数据在 `data/app.db` 单个文件里（运行时还会有 `-wal`）。

- **服务已停止**时：直接复制 `data/app.db` 即完整备份；
- **服务运行中**：**不要**直接复制——WAL 下已提交事务可能仍在 `-wal` 里，
  复制得到的文件会静默丢失最近数据。运行中的备份一律走一致快照（`VACUUM INTO`）。

理由与机制见 [ADR-003](./docs/adr/003-数据库运行形态与备份.md)。
`data/` 与 `dist/` 均不进版本库。
